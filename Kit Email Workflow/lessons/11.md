# Lesson 11

Subject: You can prompt the motion graphics too

Delay: 1 day after the previous lesson

Motion graphics are where this gets especially fun for me. You can describe an animation, have the AI build it, and refine the movement in normal language without writing every line of code yourself.

For a simple title, arrow or callout, start with your editor's tools. A keyframe sets a value at a particular moment. Put a title off-screen at one keyframe and in position at the next, for example, and the editor fills in the movement between them.

For more involved, reusable graphics, I use tools like Remotion and HyperFrames. Remotion builds motion with React code; HyperFrames uses HTML. A coding agent can create an editable project, render a video clip, and help you import that clip into your edit.

Illustration: Keep the editable motion-graphics source, render a video clip, then place it in your editor.

The [motion guide](https://github.com/paytonbilodeau/ai-video-editing-pack/blob/main/AI%20Video%20Editing%20Pack/references/MOTION%20AND%20LUTS.md) links the current setup instructions for both. Pick one route for the effect you actually need. There's no reason to install the entire internet this afternoon.

Ask your AI:

> I want a short graphic explaining this point over this shot. Compare native editor tools with Remotion and HyperFrames. Recommend the simplest route that fits my installed tools and the effect.
>
> Check current setup instructions and flag any installation or paid service before using it. Build editable source, render a short test and place it over the real footage so I can judge timing and readability.

Keep the source project, fonts and approved assets together. A rendered MP4 is useful for playback, but the source is what lets you change the wording or animation later.

The first win is one useful graphic you can revise. We can worry about the grand cinematic universe afterwards.
