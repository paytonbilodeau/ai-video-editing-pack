# 08 · Save what worked and start again

[Open the preference image](<assets/08-safe-update.png>) · [Preference-saving prompt](<../lessons/15.md>)

 

Reading time: about 2 min.

Save why an accepted correction helped, with an example the AI can find again.

![A lamp-caption correction becomes a conditional preference to keep captions clear of useful actions while preserving existing preferences.](<assets/08-learn.png>)

### 1. Save a useful preference

“Keep captions clear of the action” can help future videos. This caption’s exact height may only matter today.

> Compare my accepted edit with the earlier version and these corrections. Save clearly reusable preferences in my existing private editing profile, with an example and when each applies. Preserve the previous file and unrelated preferences. Keep one-video choices in the brief; ask if the reason is unclear. Show the saved path and changes, or say nothing needs saving. Leave the approved video unchanged and read the profile before the next suitable edit.

The lamp practice teaches keeping useful sounds and time to see the action. Its 2–9-second selection applies only to that exercise.

### 2. Start the next video

Give the AI a new recording and brief, plus the same profile. A new chat may need the profile supplied again. Check whether the saved guidance helps and what still takes too much effort.

![Compare old and new pack versions while protecting the existing private profile and projects.](<assets/08-safe-update.png>)

### When you update the pack

Keep private work outside the pack. Follow [the update instructions](<../../Payton Editing System/setup/UPDATES.md>) for that release.

> Compare this new release with my installed base and customized working copy. Preserve my editing profile, originals, project files and custom changes. Prepare the update with the included bootstrap, explain any conflicting change, and test the candidate before replacing the active pack. Keep a recoverable backup and verify the result.

![New features become eligible for public release after 14 full days from verified member release; review and publication remain separate, and critical fixes can reach both audiences sooner.](<assets/11-release.png>)

New features become eligible for public release 14 full days after verified member release, then require review and publishing. Critical fixes can reach both audiences sooner. Use the dated entry’s available download.
