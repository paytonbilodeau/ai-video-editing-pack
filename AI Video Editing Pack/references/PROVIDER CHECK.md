# Provider and Editor Check

Use this at setup and repeat it when an app, editor, connector, version, or
operating system changes. Product capabilities and license terms change. Use
current official documentation for the chosen tools and test the actual
installation; do not infer capability from an account name or old guide.

Keep an existing Final Cut, Premiere, CapCut, Resolve, or other editor when it
fits the task. If the person is choosing from scratch, recommend DaVinci
Resolve, then check the current edition, operating system requirements, and
available control route. For a complex edit, use a capable AI model with
enough reasoning and time to inspect the source and compare revisions. Check
current model options in the person's app; names and settings can change.

| Question | Evidence to record |
|---|---|
| Which AI app and interface? | Exact product, version if shown, and whether this session can read local files and run named tools |
| Which editor? | Product, edition, version, operating system, and whether a project can be saved and exported |
| Which connection, if any? | Official setup page, connector/version, read-only result, and authorization scope |
| Which optional motion tool? | Official requirements, version, local versus hosted data flow, cost, and small render result |

For each claim, label it **reported**, **officially documented**, or
**directly tested**. Save the document URL and access date in the private
project brief. Do not treat a prerequisite checker or connector listing as
proof of control.

If local access is allowed, inspect only the named working folder and tools.
Prove a read-only editor connection first. Then use copied footage in a
disposable project to import, make one reversible change, save, export, and
reopen. Record which step succeeded and which failed. A browser-only chat can
fill in the brief and guide a human through these steps; it cannot claim to
have run them.

Keep dated, app-specific permission and setup steps in the user's private
setup record. Verify the controls in the current UI before changing them.

Use the existing editor and native titles for the first test. Propose a new
installation, paid service, model download, wider access, or private-media
upload only when it solves a stated need and the user approves that action.
Do not toggle broad security settings just to make a connector work. If a
connection is unavailable, continue with a manual editor workflow.
