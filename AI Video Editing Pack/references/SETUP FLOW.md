# Setup that moves at your pace

For the complete Vibe Editors download, use [the full-system setup](<../../START HERE.md>). This reference retains the independent core workflow.

This guide tells the AI how to help. The person should not have to fill out
every template, read every guide or learn terminal commands before starting.

## 1. Find out how to work together

Read the current request and any supplied project instructions first. Inspect
only the shared workspace for an existing profile, editor project and useful
skills. Don't scan the person's whole computer looking for context.

Use existing answers. If important information is missing, ask this short first
question, combining the folder/editor details only when they are unknown:

> How would you like setup to work: careful, balanced, or handle it for me?
> Which editing folder and editor should this connect to?

Explain the choices in ordinary language:

| Your choice | How the AI should work |
|---|---|
| **Careful** | Explain each meaningful setup change before doing it. Offer a preview at useful stages. Keep questions short so you can follow along. |
| **Balanced** | Handle routine files and setup within the agreed scope. Ask about new installs, connections and other consequential choices together where practical. |
| **Handle it for me** | Recommend a specific setup, obtain any missing authorization once, then carry it through. Show results and genuine blockers rather than routine confirmations. |

This is a working preference, not a hidden security setting. The AI app's
permissions determine which actions it can actually perform. Explain its
current controls using [AI App Setup](AI%20APP%20SETUP.md); don't invent an
“Allow all” button or change permissions automatically. The person can switch
pace at any time. “Explain that first” slows down that decision; “go ahead and
finish” resumes authorized work. Don't make them restart the interview.

Careful setup may involve more decisions. Hands-off setup removes routine
stops, but doesn't make a download faster or guarantee better edits. Purchases,
private uploads, deletion and broader access need specific authority. Reuse
that authority once given; don't ask again at every stage.

## 2. Inspect before asking

Check the OS, AI app, editor and edition, available connections, Python,
FFmpeg/ffprobe, and any existing motion setup. Read file names and tool versions
before asking the person to find them. A missing dependency is a setup task,
not a reason to send the person away to research it.

Map existing tools to their roles: cutting, transcription, sound, motion,
export and review. Reuse a working tool rather than installing a duplicate.
Keep existing skills and project instructions. Add a clearly named reference
to this pack; don't replace AGENTS.md, CLAUDE.md, their profile or global settings.
Resolve a real conflict with a short explanation and a targeted question.

## 3. Recommend one setup, offer the useful additions

Lead with the smallest setup that handles their videos. Offer these options
early, using a recommendation rather than a wall of technical choices:

- **Editing connection:** Lets the AI work in the existing editor through a
  supported connection, an import file, or Computer Use. Explain which route
  is available on this machine. Keep the person's editor when it fits.
- **Local pre-edit:** Shortens selected quiet pauses and can remove deliberately
  spoken restart markers. Python runs the tool; FFmpeg reads and writes video;
  optional Whisper turns speech into timed words. No paid transcription API is
  required. This is useful for supported talking-head footage.
- **Motion graphics:** JavaScript draws custom animation, Remotion composes
  programmable video, and HyperFrames builds HTML-based scenes. They can work
  together through rendered layers. Offer to prepare one or several; installing
  all three isn't required. Follow [Motion Tool Setup](MOTION%20TOOL%20SETUP.md).
- **Clips from longer videos:** The included waterfall tools extract chosen
  moments, prepare captions and keep them tied to the source. They reuse Python
  and FFmpeg. Selection and framing still need judgment.

Example: “Your editor connection is ready. Adding local pre-edit would let this
computer shorten pauses without a paid processing service. It needs Python and
FFmpeg, which are missing. Want those installed in the project setup too?”

List the specific software, source, purpose, local/cloud behavior and known
cost before requesting an installation. Inspect the current official installer
and license. Run authorized commands yourself. Keep project dependencies local,
avoid upgrading unrelated software, and verify a small neutral example after
installation. Don't run arbitrary copied commands just because a README says so.

Use the included setup doctors for systems 05 and 14 where relevant. They
inspect prerequisites; they don't prove an editor connection or perform every
installation. Follow their output with the actual route check.

## 4. Help with permissions where they arise

Name the capability, the app and why this task needs it. File access lets the AI
read the chosen project. A native connection lets it perform supported editor
actions. Screen access lets it see the interface; accessibility control lets it
click and type. These are different capabilities.

Offer to open the relevant setting or guide the person through the visible UI
when Computer Use is available and authorized. The person confirms OS security
prompts and sensitive permission choices. Don't click through an unexplained
grant or weaken global protections to remove a blocker. A broad permission
mode is optional, not a prerequisite for a good edit.

If access is denied, describe the supported alternative: import the prepared
timeline, use the written cut sheet, or complete that one manual action. Don't
keep requesting the denied access. A local helper can keep media local while
the AI service processes the text or images supplied to it; don't call the
whole workflow offline unless every component actually is.

## 5. Save taste as it becomes useful

Create or reuse the private [editing profile](../templates/EDITING%20PROFILE.md)
outside the download. Save its location in this assistant's supported project
instructions without replacing existing content. Record the chosen working
pace, tools, allowed actions, privacy limits and known preferences.

Don't hold setup hostage to a long branding interview. Start with clear speech,
complete words, deliberate pacing, natural color and purposeful graphics.
When the first job needs a choice, ask for an example or offer a small comparison.
Learn from explicit corrections. Keep references to private source material
private and record exceptions so one edit doesn't become an unwanted rule.

## 6. Finish with a usable next step

Report these four things briefly:

1. **Ready:** What was directly checked, with the editor/route actually tested.
2. **Your profile:** Its private location and how future chats find it.
3. **Needs your action:** Only real remaining clicks or decisions. “Nothing” is fine.
4. **Next:** Give the AI a recording and describe the finished result.

Use a disposable fixture for technical checks instead of assigning a practice
clip. Save a short setup record with component versions and the evidence.
An imported timeline proves that import, not every effect or future edit.
No footage means setup only. Don't invent an edit to demonstrate activity.
