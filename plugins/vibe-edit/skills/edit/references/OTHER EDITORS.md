# Use the editor that fits the project

The editors skill holds the capability matrix, per-editor playbooks and cut-list exporter. Read the actual route before making a claim:

- [Editor connections](../../editors/references/EDITOR%20CONNECTIONS.md)
- [Resolve](../../editors/references/EDITOR%20PLAYBOOK%20RESOLVE.md)
- [Premiere](../../editors/references/EDITOR%20PLAYBOOK%20PREMIERE.md)
- [Final Cut](../../editors/references/EDITOR%20PLAYBOOK%20FINAL%20CUT.md)
- [CapCut](../../editors/references/EDITOR%20PLAYBOOK%20CAPCUT.md)
- [Cut-list interchange tool](../../editors/tools/cut_list_to_timeline.py)

Payton's strongest native automation evidence is Resolve on the tested Mac/Studio route. That does not establish the same controls in another editor, the free edition, another operating system or a future build. Keep the user's working project and tools; verify the operation actually needed.

FCPXML, FCP7 XML, EDL and cut sheets can transfer selected parts of a cut. They do not carry every effect, grade, caption, font, crop, retime or motion implementation. Import into a disposable project and check source links, frame boundaries, A/V alignment, properties and total duration. Treat unsupported effects as explicit manual steps or reviewed rendered layers with source retained.

For CapCut, native caption templates, enhancement and export often require UI work. A selected preset or 4K dimension does not establish an enhancement result. For Premiere and Final Cut, use the current documented integration/extension route when available; do not invent native scripting coverage from an interchange test. No native Premiere/Final Cut operation is claimed by the editing component's offline tests.
