# Review the exact saved result

## Clean cut, creator review, then visuals

A fresh full edit first produces polished cuts, necessary sound repairs and source-aware color on an editable timeline. When a creator wants the cut review, deliver that clean version before added captions/graphics. Preserve source-recorded demonstrations. An already approved timeline or explicit all-in-one authorization can continue without a new compulsory approval cycle.

Save the baseline, source map and DRP/DRT. Duplicate the timeline for the creator, then leave their editor alone during their pass. On return, locate the exact project/timeline they changed, snapshot it and compare disjoint source occupancy, fades, enabled audio, framing, speed and grade. Bookkeeping IDs and media usage counts are not creative changes. Do not replace their manual edit with another automatic cleanup.

When building a clean copy of a decorated timeline, disable only added overlays and their dedicated sounds. Keep the original frame sequence, dialogue, grade, recorded UI and source demonstrations. A baked decorated export is not an editable clean master; locate the underlying assembly. Verify source map and frame count across both versions.

## Technical checks

Derive expected duration and frame count from the approved edit plan, not by copying the export's own metadata back as the expectation. Check rational FPS, CFR where required, resolution, orientation, codec, audio rate/channels, color tags, full decode, start/middle/end sync and complete ending. Measure actual encoded loudness and true peak. Check a source hash before/after when a tool reads originals.

For native handoff, save/reopen the project, check media paths, source ranges, playback FPS and intended processor/track state. Export only the owned new job, with an unused path. Keep MP4, editable project and source media separately identified. A file existing, a render marked Complete or an import returning a timeline is insufficient by itself.

## Audiovisual and craft checks

Review complete retained phrases and every join with context; then inspect the actual final export at normal speed. Check complete consonants, restarts, useful breaths, screen holds, dialogue continuity, caption sync/readability and graphic entrance/hold/exit. Check a whole short at its phone-size composition. For long material, record actual coverage rather than calling a few frames a full watch.

A user approval establishes their acceptance of that version. It does not establish that the assistant listened. Numerical checks, ASR, waveform inspection and sampled stills must be named as such. If moving-video/audio perception is unavailable, label the remaining review and deliver the technically checked review copy without calling it perceptually finished.

## Deliverable record

Use the [delivery template](../templates/DELIVERY%20AND%20LEARNING.md): exact filenames/hashes, project/timeline version, available sources, checks performed, reviewer/coverage, unresolved issue, audio lineage and next action. Do not reopen approved media just to demonstrate a newly learned rule. Exporting does not authorize posting.

Keep recoverable project dependencies and originals until the owner explicitly authorizes cleanup. Do not inherit another creator's cleanup schedule or Trash policy. A source-free project export may be offline; say so. Any archival promise needs an actual restore/import check.

## Keep the creator's actual timeline

After imports or manual review, record the current project and timeline's unique
IDs as well as their names. Similar names can refer to different edits. Recheck
identity before each mutation; stop if another operation changes the active
project. Keep the returned edit, even if it differs from the original handoff.

For a native cuts-only review, deliver importable DRT and DRP files, the source
map and clear media-relink instructions. A note pointing to an open timeline
is not an editable handoff. Keep one clearly named active review version and
a useful recovery copy. Render a video when the requested review or delivery
needs it; a native-only handoff does not require a redundant MP4.
