# Editing Workflow

**The simple version:** give the AI your recording and a clear brief. Let it
make the edit, watch the draft, then describe or make your corrections. Save
useful preferences before exporting. Watch the finished file before posting.

The steps below help the assistant do that work. You can use them for an
original short or a longer video. You do not need to complete every optional
stage or fill in every worksheet yourself.

Use only the stages a project needs. Complete the requested work in one pass
unless the person asks for checkpoints. These stages are the AI's workflow,
not daily assignments for the user. Setup alone requires no footage. Record exact source and timeline versions
in the [edit plan](../../templates/core/EDIT%20PLAN%20AND%20REVIEW.md). Source footage,
private references, and account information belong in the user's private
working folder, never in this public pack.

1. **Interview and setup.** Complete [project intake](../../templates/core/PROJECT%20INTAKE.md).
   Identify the AI app, editor, OS, source media, audience, style, privacy
   limits, and chosen first result. Use the [provider check](../../../setup/references/PROVIDER%20CHECK.md)
   to verify the route and the editor's own playbook for its version facts,
   shortcuts and smoke test ([Resolve](../../../editors/references/EDITOR%20PLAYBOOK%20RESOLVE.md),
   [Premiere](../../../editors/references/EDITOR%20PLAYBOOK%20PREMIERE.md),
   [Final Cut](../../../editors/references/EDITOR%20PLAYBOOK%20FINAL%20CUT.md),
   [CapCut](../../../editors/references/EDITOR%20PLAYBOOK%20CAPCUT.md)). Keep originals untouched and
   duplicate the timeline.
2. **Source research.** Use the [source-research skill](source-research.md)
   to inventory the actual clips, audio takes, camera or
   screen recordings, and authorized references. Transcribe or index footage
   if useful, then replay doubtful words and visible demonstrations. Ground
   factual captions and claims in the recording or an approved source. Do not
   send private source material to a new service without approval.
3. **Clean cut.** Mark protected words and demonstrations, select complete
   takes, remove mistakes and dead time, and play every join. Preserve
   full words, useful breaths, and enough time to see the action. Save a
   recoverable clean-cut version. Continue within the brief; pause for a preview
   only when requested or when a material ambiguity needs the person's judgment. Use the
   [editing judgment guide](EDITING%20JUDGMENT.md) for pacing decisions and
   [EDITING CRAFT NUMBERS](EDITING%20CRAFT%20NUMBERS.md) for the defaults.
   Without a live editor connection, write the reviewed cut list and export it
   with [CUT LIST EXPORT](../../../editors/references/CUT%20LIST%20EXPORT.md) for import into the editor.
4. **Sound and color.** Listen to the entire clean cut; check sync, speech,
   joins and any processing against the original. Correct exposure, white
   balance, and shot matching. Test any LUT against the actual footage and
   discard it if it damages detail or skin. Keep adjustments editable. The
   [audio guide](AUDIO%20GUIDE.md) shows source-specific comparisons.
5. **Graphics when useful.** If the brief calls for a title or annotation, put
   it on a separate track. Skip this stage when the recording already explains
   the point clearly and no graphics were requested. Use an authorized reference for a specific purpose, then test its
   timing, reading time, contrast and coverage on moving footage. Native
   editor tools can handle simple titles. JavaScript, Remotion and HyperFrames
   are complementary options for custom work; use the appropriate route or
   combine their rendered layers. Follow [Motion Tool Setup](../../../style/references/MOTION%20TOOL%20SETUP.md).
6. **Review, learn and deliver.** Watch the final draft in its editable timeline.
   Apply feedback or make small manual changes on a duplicate. Compare the
   earlier and approved versions through the connection when it can read the
   relevant state; otherwise use exports and timestamped notes. Save useful
   recurring preferences, with the reason and when they apply. Keep one-video
   exceptions in the brief. Then save and reopen the project. Export the exact
   version, check the file decodes and ends properly, then watch and listen
   to it. Record what was technically checked, what a person reviewed, and
   what remains open in [delivery and learning](../../templates/core/DELIVERY%20AND%20LEARNING.md).
   Preserve the accepted timeline before revisions. If an external audio finish
   is selected, run it once after all visual work, using the agreed preset. Keep
   the pre-service master and verify the returned file before delivery. Build
   derivatives from the pre-service master so each finished version receives
   only one audio pass.
7. **Reuse what helped.** Test saved preferences on the next suitable video.
   For a short from a longer video, keep one complete idea with enough setup
   and a clear payoff. Make only the requested versions. Use the
   [reframing guide](REFRAMING.md) for moving faces and platform controls, then
   review each finished file. Publishing is a separate action.

An assistant should stop and report a limitation when it cannot inspect the
source, operate the selected tool, or verify the exact output. A plan is
useful, but it is not an edit. A technical export check is useful, but it is
not a person's viewing and listening approval.
